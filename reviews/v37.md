# アプリ版の点検 v37（2026-10-21）
変えた所：🎤を押すとすぐ OFF になる不具合を直した（satouさん「マイクを押してもすぐOFFになる」「動作確認は行ってから、レビューの依頼を」）。
- 原因：Android の Chrome は、端末の音声認識を別のしくみで動かす。会話中に割り込み用としてページがマイクを持ったままだと、話す前に audio-capture で終わる。2回続けて聞こえないと🎤を止めていた。関連：w3c/speech-api の課題 #66（https://github.com/w3c/speech-api/issues/66）、MDN SpeechRecognition.available / processLocally。
- 端末の音声認識で聞くときは、ページ側のマイクを持たない（割り込み用のマイクは耳＝Whisper のときだけ）。
- それでも端末の音声認識がすぐ終わる端末で、耳が入っていれば、その場で耳で聞き直す。その日は耳で聞き、切り替えたことを一言出す。
- 耳が無ければ、1回目で理由を日本語で言う（「マイクを使えなかったよ」など。英語のエラー名は出さない）。耳の入れ方を案内し、打つ形に切り替える。
- 🎤がすぐ止まった日は、この端末の様子（失敗の種類と秒数だけ。話した中身・カードは入れない）を1日1回、自動で local-board/diagnostics/ に送る。送ったことも一言出す。

## 交代の視点：スマホ（37 ÷ 5 の余り 2）
- Pixel 7 の幅（412px）・タッチ・CPU 4倍遅くで、押す → 話す → 文字が出るを通した（再現の記録）。
- Android の Chrome は、端末の音声認識とページのマイクを同時に持てないことがある。ページ側でマイクを持つのは耳（Whisper）のときだけにした。
- 耳（Whisper）の計算は別の Worker なので、遅い端末でも画面は固まらない（v34 から変わらない）。

## 検査に足したもの
- qa/run.mjs に足した項目は次のとおり。
  - Android のまねで話す前にマイクを持っていると失敗する端末で、端末の音声認識が通る。
  - いつも失敗する端末・耳なしで、1回目で理由と次にすることを日本語で言う。
  - 耳ありなら耳で聞き直して文字にし、その日は耳で聞く。切り替えを知らせ、診断を1日1回送って送ったと言う。診断に話した中身・カードを入れない。
